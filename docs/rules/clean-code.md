# Clean Code

- Use descriptive names that reveal purpose. Avoid unexplained abbreviations.
- Replace repeated magic values with named constants when they carry domain meaning.
- Keep each function or class focused on one responsibility.
- Prefer composition and small explicit helpers over duplication or deep inheritance.
- Comments should explain why, non-obvious constraints, public APIs, or side effects; do not narrate obvious code.
- Keep implementation details behind clear interfaces at architecture boundaries.
- Refactor only when it improves the task at hand. Leave unrelated code alone.
